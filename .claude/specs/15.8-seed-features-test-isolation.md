# Spec: Seed Features Test Isolation

## Roadmap description
Tests that reset the pipeline history table can no longer wipe real feature test and review records.

## Overview
On 2026-08-08, truncating the live `features` table and calling `seed_features()` to reseed it (something five existing test files do for isolation, since there is no separate test database) triggered a data-loss incident: `test_report`, `review_report`, and `deployed_at` came back NULL for every row, including features that were genuinely tested, reviewed, and shipped. Three mechanical bugs in `/ship-feature`'s `seed_features()`-regeneration script caused this (a dropped tuple field, an INSERT column/placeholder mismatch, and `re.sub()` backslash-escape corruption) and were already fixed and shipped directly to `main` in commit `cce2e1a`, bypassing the normal pipeline as an emergency fix. This release addresses the remaining design gap: the five test files still `TRUNCATE features RESTART IDENTITY CASCADE` against the real `DATABASE_URL` and commit that truncate, so any *future* bug anywhere in the seed/reseed path could destroy live pipeline history again. Investigation during implementation planning confirmed that a naive rollback-based fix is not sufficient by itself: every mutating helper in `database/db.py` and `database/queries.py` (including `seed_features()`) calls `conn.commit()` internally, and because all five test files monkeypatch `get_db()` to return the same shared connection, a `SAVEPOINT` on that connection is released the instant any app helper commits — this is exactly why the original test author's docstring already documents rejecting rollback in favor of TRUNCATE. The chosen fix is to make the app code's commits themselves inert for the duration of each test (monkeypatch `conn.commit()` to a no-op on the same shared proxy already used to fake `get_db()`), and perform exactly one real rollback at teardown — so nothing a test does, directly or via app helpers, is ever actually persisted to the live database.

## Release context
Single release under feature 15 (Developer Roadmap Page) — release 15.8, no sibling releases in this plan. In scope: converting the isolation strategy of the five affected test files, and adding a regression test that guards `seed_features()` structural integrity and round-trip fidelity going forward. Out of scope / deferred: a dedicated `TEST_DATABASE_URL` or Postgres schema for test isolation — identified as the higher-leverage long-term fix but explicitly deferred in favor of the lower-lift no-op-commit approach for this release (see `.claude/features/releases/15.8-seed-features-test-isolation.md`, "Deferred / Out of scope"). No production code in `database/db.py`, `database/queries.py`, or `.claude/commands/ship-feature.md` changes in this release — the mechanical bugs are already fixed in `cce2e1a`; this release only changes test fixture code and adds new tests.

Resolved during implementation planning (was an open question in the release plan): the isolation mechanism is no-op `commit()` + single final rollback, not plain `SAVEPOINT`/rollback — see Overview above for why savepoints don't survive the app code's internal commits on a shared connection.

## Error handling
- If a test's no-op `commit()` patch is accidentally applied to a connection other than the shared test proxy (e.g. a connection opened directly by test setup code, outside `get_db()`), that would silently break isolation for that path — the fixture must ensure the no-op is applied to the exact same proxy object returned by the patched `get_db()`, matching the existing pattern precisely.
- If `rollback()` at teardown fails (e.g. because the connection is already in a failed-transaction state from an unrelated error mid-test), the fixture must not mask that failure — let pytest surface it rather than swallowing the exception, so a broken isolation guarantee is visible rather than silently accepted.
- The regression test's row-tuple/placeholder-count assertion must fail loudly (not skip or pass-by-default) if `database/db.py`'s `seed_features()` is refactored in a way this test can't introspect — prefer exercising the real function against a real (rolled-back) table over parsing source text, so the test tracks behavior rather than implementation detail.

## Rules for implementation
Read `CLAUDE.md` for full project conventions. Specifically for this release:
- No SQLAlchemy or ORMs — not applicable here (no new queries), but the regression test must use raw `psycopg2` if it touches the DB directly, consistent with the rest of the codebase.
- Parameterised queries only — the regression test must not interpolate any values into SQL strings.
- Do not modify `database/db.py`, `database/queries.py`, or `.claude/commands/ship-feature.md` in this release — those already contain the fix from commit `cce2e1a`; this release is test-code-only.
- Preserve the existing `_NoCloseProxy` pattern exactly as-is for `.close()` — only extend it (or wrap it) to also no-op `.commit()`; do not restructure the connection-patching approach beyond what's needed for this fix.
- Every one of the five modified test files must still pass its full existing test suite unmodified in behavior — this release changes *how* isolation is achieved, not what each test asserts.
