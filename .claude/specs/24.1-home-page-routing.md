# Spec: Updating Oxos Homepage

## Roadmap description
A public marketing homepage at the root URL so new visitors can explore the Oxos Platform before signing in.

## Overview
The Oxos Platform currently serves the authenticated `platform.html` template at `/`, meaning unauthenticated visitors see the app interface instead of a marketing landing page. This release creates a dedicated public homepage at `/` using the existing `home-option-f.html` mockup, converts it into a proper Jinja2 template, and adjusts routing so the homepage is public while `/platform` remains the authenticated application entry point.

## Release context
Release 1 of 1 — MVP. The scope covers the full homepage integration: template creation, CSS extraction, routing changes, auth-flow adjustments, navigation updates, and SEO metadata. No code splitting or advanced performance optimization is included in this release.

## Depends on
Nothing — this is a new feature.

## Routes
- `GET /` — new public homepage rendering `home.html` (public)
- `GET /platform` — existing authenticated app route, unchanged (logged-in)

No new routes are added. The existing `/` route is repurposed.

## Database changes
No database changes.

## Templates
- **Create:** `templates/home.html` — new Jinja2 template extending `base.html`, rendering the homepage mockup content
- **Modify:** `templates/base.html` — add favicon link in `<head>`

## Files to change
- `app.py` — update `landing()` to render `home.html`; update redirect targets
- `templates/base.html` — add favicon
- `templates/home.html` — new file

## Files to create
- `templates/home.html`
- `static/css/home.css` — extracted and cleaned CSS from the mockup

## New dependencies
No new dependencies.

## Error handling
- If the homepage template fails to render, Flask's default error handling applies
- No form input validation is needed on the homepage (it is a static marketing page)
- Auth guards on protected routes (`/platform`, `/profile`) remain unchanged

## UI/UX notes
- The homepage must be fully responsive (mobile-first, using existing breakpoints from `style.css`)
- All links must be descriptive (no "click here" — use meaningful text)
- The "Get Started" button links to `/login`
- Navigation links (logo, home) link to `/`
- Logout returns the user to `/` (the new homepage)
- Colour contrast must meet WCAG AA (the mockup uses `--accent` green on white, which passes)
- The homepage must not load any authenticated-only JS bundles

## Rules for implementation
- No SQLAlchemy or ORMs — use raw `psycopg2` queries only
- Parameterised queries only — never interpolate user data into SQL strings
- Passwords hashed with werkzeug — `generate_password_hash` / `check_password_hash`
- Use CSS variables — never hardcode hex values
- All templates extend `base.html` — use `{% extends "base.html" %}`
- Auth guard on every protected route — check `session.get("user_id")` and redirect to `/login` if missing
- Ownership check on all expense mutations — queries must include `AND user_id = %s`
- Flash messages for all user-facing outcomes — success and error states
- Currency displayed in ₹ — format amounts as `₹{amount:,.2f}`
- Dates stored as `YYYY-MM-DD` strings — validate with `datetime.strptime(value, "%Y-%m-%d")`
